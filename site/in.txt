## Plus 11 pre-existing "redirect to homepage" rules that violate your stated policy

Found in the current `next.config.mjs`:

```
/elementskit-content/:path*  →  /

/tag/northern-virginia-decks →  /
/tag/:path*/feed/:path*      →  /
/drafts                      →  /
/home-2                      →  /
/wp-content/:path*           →  /
```

These all **dilute homepage signal** and tell Google "WordPress feed/junk == homepage content," which is a soft quality penalty. Per your rule "do not redirect everything to homepage" — these should change to either remove the rule entirely (let them 404) or use a proper 410 Gone via a small middleware.

## What I'm proposing

### A) **One** new redirect rule (the only real 404 with a clean modern equivalent):

```js
{ source: '/choosing-right-deck-material-wood-vs-composite', destination: '/composite-deck-vs-wood-deck-virginia', permanent: true }
```

I verified `/composite-deck-vs-wood-deck-virginia` returns **200** ✅.

### B) **Remove** the 11 "redirect to homepage" rules

Delete them from the array. The URLs will then return **404 Not Found** — which is the correct signal for "this page no longer exists." Google will eventually drop them from its index. **No user is hitting these URLs except crawlers and bots; redirecting them to homepage was actively harmful.**

For the truly-WP-junk ones (`/wp-content/:path*`, `/elementskit-content/:path*`, `/comments/feed`, all `/tag/*`), this is an unambiguous improvement.

For `/drafts` and `/home-2`: per your explicit instruction (`"home-2/ → 410 or leave 404, not homepage"`), removing them = they return 404. Good.

### C) **Optional** — proper `410 Gone` for the WP junk

Next.js `redirects()` doesn't support 410 directly. If you want true `410 Gone` (stronger "delete this from index now" signal than 404), it requires a tiny `middleware.ts` file. I can add that, but it's a **separate, optional step** — recommend skipping for now to keep this patch surgical.

### D) **NOT in this patch** (deferred)

- `/marker-listing` — leaving as 404 (Squarespace internal, no SEO value, no clean modern equivalent)
- `/showcase` redirect chain investigation — that's part of the "Duplicate canonical" cleanup (a separate audit)
- `/wp-login.php` 403 — system response, fine
