## 3. Meta CAPI validation (requires env vars)

Prerequisite: `META_PIXEL_ID`, `META_CAPI_ACCESS_TOKEN`, `META_CAPI_TEST_EVENT_CODE=TEST_QA` set in `.env.local`. Restart `npm run dev`.

### 3.1 Meta CAPI fires on form submit

1. Open Events Manager → your Pixel → **Test Events** tab → "Test server events" section
2. Submit a form on `/contact`
3. Wait 10-30 seconds, refresh Test Events tab

**PASS:** A "Lead" event appears with:
- Source: Server
- event_id matching the form's event_id (visible in details panel)
- 8-9 match keys (`em`, `ph`, `fn`, `ln`, `ct`, `st`, `zp`, `country`, `fbc`)
- EMQ (Event Match Quality) score ≥ 7.5

**FAIL signals:**
- Event missing → check Vercel/dev logs for "Meta CAPI" errors; verify env vars
- EMQ score < 5 → most match keys are missing; verify form fields populated
- Event appears but Source: Browser → server CAPI didn't fire; only client Pixel did

### 3.2 Meta Pixel Helper validation (Chrome extension)

Install [Meta Pixel Helper](https://chromewebstore.google.com/detail/meta-pixel-helper/fdgfkebogiimcoedlicjlajpkdmockpc) (Chrome extension).

1. Visit `http://localhost:3000/contact` (no Meta Pixel installed yet via GTM in this test, so extension won't see anything)
2. Once Meta Pixel IS installed via GTM later:
   - Helper icon should turn blue when Pixel detected
   - Click icon → see Lead event details on /thank-you

**PASS (after GTM Pixel install):** Helper shows Lead event with event_id matching what /thank-you fires.

### 3.3 Deduplication verification (client + server)

After GTM Pixel install + Meta CAPI env vars set:

1. Submit a form
2. Events Manager → **Overview** → wait 10 sec → check Lead event count

**PASS:** One submit produces exactly ONE Lead event counted (despite both client Pixel and server CAPI firing — Meta deduplicates on event_id within 7 days).

**FAIL signals:**
- Two Lead events counted → event_id wasn't passed correctly; one of the paths used a different identifier
- Zero Lead events → both Pixel and CAPI failed

### 3.4 EMQ score expectation

Loudoun Decks form captures: email, phone, first name, last name, city, state, zip.

After CAPI + Pixel both firing with full match keys, EMQ should be:

| Score | Quality |
|---|---|
| 8.0-10.0 | **Excellent** — full match keys + IP + UA + fbc + fbp |
| 6.0-7.9 | **Good** — full match keys but missing fbc/fbp/IP |
| 4.0-5.9 | **Fair** — partial match keys |
| < 4.0 | **Poor** — missing critical match keys |

**Loudoun Decks target: EMQ ≥ 7.5** given the form fields collected.

## 4. Edge cases and resilience

### 4.1 No env vars (Meta CAPI no-op)

1. Remove `META_PIXEL_ID` from `.env.local`, restart dev
2. Submit form

**PASS:** Form submits successfully. Email arrives. No CAPI errors in logs. (Internally: `sendMetaLeadEvent` returns `{success: false, skipped: true}` and the `.catch()` swallows nothing.)

### 4.2 Invalid Meta env vars

1. Set `META_PIXEL_ID=invalid` and `META_CAPI_ACCESS_TOKEN=invalid` in `.env.local`, restart dev
2. Submit form

**PASS:** Form submits successfully. Email arrives. Server logs "Meta CAPI non-2xx: 400 {...}". The error is logged but does not break form submission flow.

### 4.3 Ad blocker active

1. Install uBlock Origin or similar
2. Submit form

**PASS:** Click-ID capture still works (capture script is part of your own domain, not blocked). dataLayer events fire. CAPI still fires server-side. Only client-side Pixel call (when GTM is installed) is blocked — but CAPI compensates with the same event_id.

### 4.4 Cookies disabled

1. Browser → Settings → block all cookies
2. Visit `http://localhost:3000/?gclid=test`
3. Submit form

**PASS:** No cookies set (expected). `getClickIds()` returns all nulls. Form submits. No attribution block in email (correct — no click IDs to surface). CAPI fires without `fbc` field (lower EMQ but not broken).

### 4.5 SSR safety

`getClickIds()` and `trackLeadConfirmed()` both check `typeof document/window === 'undefined'` and no-op on server.

**PASS:** No "document is not defined" errors during SSR. Verify by running `npm run build` (uses SSG for many pages — if SSR-unsafe code paths existed, build would fail).

### 4.6 Hydration mismatch check

`ThankYouTracking.jsx` returns `null` and runs side effects in `useEffect`. No DOM output.

**PASS:** No hydration warnings in Console on `/thank-you` page.

### 4.7 Edge runtime check (not currently used)

`src/server/metaCapi.js` uses Node's `crypto` module. This is NOT compatible with Vercel Edge Runtime.

**Currently safe:** `src/server/sendEmail.js` and `src/server/metaCapi.js` are Server Actions, which default to Node.js runtime — not Edge. No explicit `export const runtime = 'edge'` declaration in either file.

**If migrating to Edge in the future:** Replace `crypto.createHash('sha256')` with `Web Crypto API`:
```js
const hash = async (v) => {
  const buf = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(v.toLowerCase().trim()));
  return [...new Uint8Array(buf)].map(b => b.toString(16).padStart(2, '0')).join('');
};
```
