## 🎯 Real causes of the 3.0s mobile LCP

After reviewing the actual code, the LCP issue is **NOT** caused by missing optimizations — it's caused by these specific things:

### Cause 1: Hero is `"use client"` because of `useContact`
`Hero.jsx` is a client component (`"use client"`) just to call `openContact()` on a button click. That delays hydration and pushes LCP later on mobile.

### Cause 2: Hero image is 169 KB at 1536×1024 — a bit large for mobile
Mobile devices download 169 KB but only use ~390px wide. The `sizes="100vw"` + `next/image` should be serving smaller variants — verify it actually is.

### Cause 3: `PromoModal` is dynamically imported but renders early
A modal at the top of `<main>` can interfere with hero paint timing if it renders any DOM during hydration.

### Cause 4: `image/avif` format may not actually be served
The next.config has `formats: ['image/avif', 'image/webp']`, but the hero file is `.webp` (not auto-optimized through `_next/image`). If Next.js isn't generating an AVIF variant at runtime, the browser downloads the WebP.

### **Patch 2** — `src/components/HeroCTA.jsx` — New tiny client island
```jsx
"use client";
import { useContact } from '@/context/ContactContext';
import { trackPhoneClick } from '@/lib/tracking';
import styles from './Hero.module.css';

export default function HeroCTA() {
  const { openContact } = useContact();
  return (
    <div className={styles.buttonGroup}>
      <a href="tel:+15716557207" className={styles.ctaButton} onClick={trackPhoneClick}>
        Call Now: (571) 655-7207
      </a>
      <button onClick={openContact} className={styles.ctaButtonAlt}>
        Get Free Estimate
      </button>
    </div>
  );
}
```
**Why:** This isolates the client-side code to just the CTA buttons. The hero text + image now render as a **server component** — the H1, image, and trust badge ship as static HTML, paint immediately, no hydration delay. This typically shaves **400–800 ms** off mobile LCP.
